# 给执行 Agent：从零搭建单设备海外家宽出口

将本文件作为任务指令交给**能访问设备和路由器的 Agent**。本仓库是公开示例，不能提供你的登录权限、域名或真实配置。不要把“读完文档”当成部署完成。

## 先选最少需要的功能

先问我需要“临时整机切到家宽”还是“指定域名走家宽、其余直连”。两者都先完成 [救援通道](remote-admin.md)。前者随后按 [Exit Node](exit-node.md) 完成即可；只有后者采用下方 HY2 任务和完成条件。零环境意味着由你检查、安装和配置，不代表零账号、零授权、零硬件成本或保证可用。

## 任务和完成条件

在我拥有或获授权管理的海外家庭网络中，为**一台主力设备**建立 HY2 规则分流：我指定的域名经家中常开主机和家庭宽带出网，其他网站直连。先盘点公网入站条件和客户端能力：公网 UDP 可达时建立最小映射；CGNAT 或无可用公网入口时评估 Tailscale 私网 HY2。若平台无法同时运行两种客户端，报告分流目标尚未完成，并提供已验收的 Exit Node 整机保底。Tailscale 同时承担远程管理，不与 HY2 客户端同时接管整机默认路由。

完成需有六项证据：①主机正常联网；②主力设备在家庭外网络能连接 HY2；③服务端认证且有双向数据；④指定域名命中海外规则且呈现家宽出口；⑤未指定域名命中 DIRECT；⑥主机重启后服务恢复，远程管理通道仍可用。少一项就报告相应状态，不能写“全部完成”。

## 执行规则

- **立即开始只读盘点，再执行能做的配置。**不要只输出教程、架构图或待办。先记录改动前的网络、服务、监听、规则和可回退文件；不得覆盖已有实例。
- 不假设主机系统、路由器品牌、公网 IP、端口、证书、域名、现有 HY2/Tailscale 状态或管理员权限。所需端口从当前空闲范围中选择并实测，不能照搬示例或其他生产配置。
- 只在必需时向我问：哪台是主力设备、想走海外出口的域名、无法从设备读取的登录/管理方式，以及会中断现有网络的操作。密码让我在本机安全输入，不要要求贴到聊天里。已得到的授权不重复索取。
- 先查 [Hysteria 服务端](https://v2.hysteria.network/docs/getting-started/Server/)、[客户端](https://v2.hysteria.network/docs/getting-started/Client/)及所选规则客户端的当前官方文档。新建独立服务、强随机认证凭据和有效 TLS 校验；不得设置 `insecure: true` 或 `skip-cert-verify: true`。若自签，客户端必须信任相应 CA 并校验证书名称；做不到就选择可验证的证书。
- 私钥和密码只放在获授权的受限位置；报告和提交记录不含公网地址、精确位置、密钥、路由器管理入口或原始日志。不要把填好的配置放进这个 Git 仓库。
- 每项改动都先保存旧状态，改后读回；一旦发现会中断现有连接的风险，说明具体影响并在该步请我配合。不能控制手机/路由器时，准备准确的界面操作并与我同步验收，不能代填“成功”。

## 执行顺序

### 1. 盘点和远程管理

确认主力设备的系统与客户端能力、常开主机的系统和版本、当前代理/VPN、主机局域网地址、默认网关及已有 HY2 监听。先确认有人能在家中主机上安装软件并完成首次登录；若主机不在手边且没有获授权的现成管理通道，停在这个真实阻塞。按 [救援通道](remote-admin.md)部署并验证 Tailscale、获授权的 SSH/图形远控、密钥到期和无人值守电源行为。验证从家庭外网络**实际登录或管理**主机；仅有 `ping` 成功不算。不要开启 Exit Node 来做 HY2 配置。

### 2. 确认入口并选 HY2 路径

按 [家庭公网入口](home-nat.md)只读检查路由器 WAN、出口地址、上游 NAT、已有规则和外部 UDP 可达条件。公网候选仍须从外部验证；此时可继续步骤 3。若确认没有可用公网入口，或公网 UDP 异网验收失败，且主力设备可同时保持 Tailscale 与规则客户端，就按 [私网路径](private-path.md)和[常开主机部署](server-host.md)新建 HY2 服务，仅通过 Tailnet 地址接入。Mac 客户端参照 [Clash Verge 分支](mac-clash.md)。先用不接管整机的代理模式测试；若确需 TUN，再检查路由回环，并保持 Exit Node 关闭。异网通过即可跳过步骤 3。

若主力设备不能同时运行这两个网络客户端，不能把私网 HY2 写成“单设备规则分流成功”。普通 iPhone 单 VPN 场景可用单独验收过的 Exit Node 整机保底；如仍要求手机按域名分流，需要另行确定可达入口。不要将保底当成分流。

### 3. 有可用公网入口时建公网 HY2

服务端安装与开机启动参照[常开主机部署](server-host.md)。若有公网候选，先固定主机局域网地址，挑选未占用的外部和内部 UDP 端口，安装独立 HY2 服务并确认本机监听，再**只添加一条** UDP 映射。优先手动映射；UPnP、DMZ 或修改现有规则不得擅自使用。通过家庭外网络的真实 HY2 认证和页面请求确认入站路径。

若无可用公网入口，不要声称映射成功；给我列出证据与可行替代（例如已测通的私网路径、可用 IPv6 或需另行决定的中转）。不要自行购买服务。

### 4. 配单台客户端并验收

按设备平台使用兼容 HY2 的规则客户端：[Mac / Clash Verge](mac-clash.md) 可从 [Mihomo 示例](../examples/mihomo.example.yaml)生成本次配置；[iPhone / Shadowrocket](iphone-shadowrocket.md) 和 [Android](android-client.md) 按实际版本逐项填入并验收。普通 iOS 单 VPN 场景不能同时运行 Tailscale 隧道与 Shadowrocket 隧道；不反复尝试双开。**先取得域名清单，再写规则；末尾使用 DIRECT。**区分“系统代理仅覆盖遵循代理设置的应用”和“TUN 捕获更广的流量”，用实际应用验证所选模式。

按 [验收表](validation.md)进行家中基线、家庭外网络、持续使用、断开重连和网络切换测试。家庭内直连与代理可能共用同一个出口 IP，所以家中测试不能证明规则与公网入口正确。测试 DIRECT 时记录规则命中，并在外部网络核对真实出口；测试 HY2 时同时查看客户端与服务端证据。

### 5. 恢复和交付

链路通过后才设置开机启动、健康探测与必要的 DDNS；验证主机重启和连接恢复。若使用手动静态映射，不编造 UPnP 续租脚本。写出日常 HY2 分流与临时关闭代理的操作。若用户还要求 Tailscale Exit Node 整机保底，则单独配置该节点、完成 Tailnet 管理端批准和异网验收，再写切换步骤：切 Exit Node 前先关闭客户端整机代理/TUN，切回 HY2 前先关闭 Exit Node。未配置或未验收的 Exit Node 不得列为可用保底。

中国侧测试是**可选的额外验收**：你不能替我找朋友、联系朋友或假定有中国测试端。若我提供愿意协助的人或获授权设备，给我一份五分钟测试步骤，由我转交，并记录其网络、时段、真实页面结果、重连结果。若没有，部署继续完成；报告写“中国侧可达性与晚高峰质量待回国验证”。中国侧需用当地普通 SIM/宽带，并核对直连出口；境外 SIM 在中国漫游也可能回归属地出网，不能冒充本地运营商样本。日本本地测试不能冒充中国侧测试，也不能承诺保证不卡。超时只记录事实、换网对照和两端日志，不直接归因于防火墙。
